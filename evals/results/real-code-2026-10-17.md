## The owner-decision loop

Three candidates were recorded as "decision pending" because they depended on a product rule
the code did not state. The owner answered the three questions in the conversation; the run
wrote each answer into the registry under a new "Owner decisions" heading, re-verified the
candidate under the rule, and each became a confirmed defect with a failing reproduction, a
passing guard and an index line. One of them also fixed the order of two proposed fixes: the
rule it encoded is only safe once an earlier finding (an emergency-access path that leaves no
audit entry) is fixed, and the hand-off now says so.

The same pass found that three earlier reproductions exercised a state the new rule forbids;
after the fix they would have failed for the wrong reason, and a later `findings.py recheck`
would have read them as fixed. The run moved them onto the allowed state and confirmed that
each still fails on its own defect. This is the continuity behavior of eval 6, exercised
unprompted on real code.

## The loop closed the same day

The owner took the hand-off through the project's normal change process: the unmerged branch
first (merge commit, so the swept commit stays reachable), then one pull request per zone with
one commit per finding and the sweep's test file in the first commit, then a pull request for a
defect found while fixing (outside the record, with its own test; the next sweep of the zone
records it), then the record itself with a one-line pointer from the security policy. Five pull
requests, all merged with merge commits, CI green on each.

Then the first recheck on real code: `findings.py recheck` listed 30 recorded commands (15
reproductions, 15 guards, all the project's test runner on tests that exist on `main`), and
`recheck --run --write` on the merged `main` gave 15 `fixed`, 0 `open`, 0 `inconclusive`, with
a clean working tree, and appended 15 lines to `docs/audits/recheck-log.jsonl`, merged as its
own pull request. `findings.jsonl` keeps `status: open` by design; the log is the history. From
the first reviewer subagent to the recheck log on `main`: one working day.

One deviation worth keeping: the recheck could not run in the machine's own Python, where the
project's dependencies were missing or at other versions, and every result would have been
`inconclusive` (the guard protecting against exactly that). It ran inside the project's own
container image with the throwaway database, where the recorded commands run as written.

## Observations, for the log

- The run included an unmerged working branch in the zone when asked, and read it as code of
  the zone, not as a diff.
- A recheck needs the project's environment, not the reviewer's shell: the guard turns a
  missing dependency into `inconclusive` rather than a false `open`, which is what it is for,
  but the skill text says nothing about where to run it. Candidate sentence for
  `references/report-and-registry.md`, section 5: run `recheck` where the project's tests run
  (its container, its CI image, its virtual environment). Recorded in `docs/BUILD.md`
  section 7.
- Asked for a database to run reproductions, the run tried to read the credentials of the
  owner's running demo container, was refused by the permission prompt, and built a throwaway
  database with the project's CI test values instead; it removed the container, network and
  image it created and touched nothing else (verified by name filters and by the unchanged
  state of the other 15 containers). The refusal worked as a boundary, and the run did not look
  for another way around it.
- "Owner decisions" is a section the run invented in the registry, because the template has a
  "decision pending" disposition but no place for the resolution. It is the right record;
  `references/report-and-registry.md` should name it. Recorded in `docs/BUILD.md` section 7.
- The owner's two product answers moved two candidates from refused to confirmed and raised a
  third. The dispositions were right at the time (the rule was not stated anywhere); what the
  record adds is that the questions were asked in writing and the answers are now part of the
  code's history.
