### The regression

In the audit-trail zone the run found that two concurrent audit writes on the same record fork
the hash chain, so the record's audit shows as broken from then on and a stray branch can be
deleted by someone with database access without the chain noticing. The run wrote that this
was partly caused by a fix merged the same morning: the fix for an earlier finding (emergency
access leaving no audit entry) wrote one entry per request, and one page load sends several
requests in parallel. Its words: "AU2 is partly my doing".

What this says about the skill, written as a limit: the skill verifies defects, not fixes. A
"fix approach" in a report is a proposal by a reader of the handler and its route, not of the
concurrency model, and the fixes of 2026-10-17 were merged without a verify-fix pass, although
the skill has that mode. One fix proposal in fifteen produced a High finding. What worked is the
record: the new finding cites the fix that caused it and the commit, the earlier finding stays
fixed, and the recheck stays clean. The fix for the fork went in as a database constraint
(uniqueness on record and previous entry, declared so that null values are not distinct) with
the write checked inside a savepoint and retried on the new head, and the emergency-access
entry became one per session and record for reads. A later run marked the forks that already
existed as historical rather than breaks.

Recorded in `docs/BUILD.md` section 7: a hand-off that proposes fixes says that a fix pull
request goes through verify-fix before merge.

What the run exposed in the skill, now the v1.4.1 candidates (`CHANGELOG.md`, Unreleased):
the mandatory citation check printed credential lines into the session transcript (fixed:
masked output); nothing mechanical checked the deliverables for the repository's own secret

assumed it runs in the owner's repository, and a stop hook in the environment twice asked the
run to commit and push the record to the public repository (an external-review section for the
skill text, pending); `sweep_status.py` reported a broken extraction on every first run (fixed).

Limit: one external run, by the skill's author, on a repository with unusually many defects in
